# dvx SP0 + SP1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the dvx core dev loop — plugin SDK, testing helpers, analyzers, deterministic IDs, `describe` / `verify` / `deploy` against the shared dev environment — plus the SP0 spikes that gate it.

**Architecture:** All logic in `Dvx.Core` (net8.0); `Dvx.Cli` is a thin System.CommandLine layer emitting `Dvx.Contracts` JSON. The SDK and testing helpers are shared projects compiled into consumer net462 plugin assemblies; `Dvx.Core` reads built DLLs only through `MetadataLoadContext`. IDs are UUID v5 over frozen identity keys; there is no lock file.

**Tech Stack:** .NET 8, C# 7.3 (SDK), MSTest, FakeItEasy, Roslyn 4.8, Microsoft.PowerPlatform.Dataverse.Client, Microsoft.Identity.Client.Extensions.Msal, System.CommandLine, System.Reflection.MetadataLoadContext.

**Spec:** `SPEC.md` (v2). Read sections 3–13 and Appendix B before any task.

## Global Constraints

- `Dvx.Core`, `Dvx.Cli`: net8.0. `Dvx.Contracts`, `Dvx.Analyzers`: netstandard2.0. SDK and testing: shared projects, C# 7.3, net462, all types `internal`.
- Dependencies only from SPEC §11: `Microsoft.CrmSdk.CoreAssemblies`, `Microsoft.PowerPlatform.Dataverse.Client`, `Microsoft.Identity.Client.Extensions.Msal`, `System.Reflection.MetadataLoadContext`, `System.CommandLine`, `Microsoft.CodeAnalysis.CSharp` 4.8.x (analyzers only), `MSTest`, `FakeItEasy`. Anything else: stop and ask.
- Central package management (`Directory.Packages.props`); nullable enabled outside the SDK; `TreatWarningsAsErrors=true`.
- Tests that build or run net462 code require Windows.
- No secrets, tokens or record data in files, logs, output or test data. Integration credentials come only from environment variables `DVX_IT_URL`, `DVX_IT_CLIENT_ID`, `DVX_IT_TENANT_ID`, `DVX_IT_SECRET`.
- Never load plugin assemblies for execution; `MetadataLoadContext` only.
- Identity namespace GUID: `b3f5d2a1-7c4e-4f8a-9d61-2e0c5a7b9f13`. Never changes after Task 6 ships.
- Exit codes (SPEC §12): 0 success, 1 diagnostics, 2 usage, 3 credentials, 4 env not allowed, 5 env changed since plan, 6 confirmation required, 7 partial `--all`, 8 Dataverse/network after retries, 9 internal.
- Comments and identifiers in English. One milestone per session; stop at milestone boundaries (M0, S-A/S-F, M1 … M6).

## Review Focus

1. **Environment-only components without a lock file.** The spec distinguishes "own delete" from "foreign" but nothing records who removed a class. Rule used here: an environment-only component is *own delete* when the assembly's current stamp names the current branch; otherwise (other branch, `unknown`, or no stamp) it is *foreign*. Test in Task 15.
2. **Case changes in message, table or unique names** (`"Update"` → `"update"`) must not change any ID. Test in Task 6.
3. **An assembly with the same name already in the environment but a different ID** (created outside dvx, e.g. by PRT) must be a plan error (`DVX206`), never adopted or overwritten. Test in Task 15.
4. **Apply interrupted mid-way** (failure or Ctrl+C) followed by a re-run must converge to an empty plan. Test in Task 16.
5. **Git missing, detached HEAD, or non-ASCII user name** must still produce a valid stamp that round-trips through `StampParser`. Test in Task 15.
